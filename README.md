# Booth Import Manager

BOOTH에서 산 에셋을 **클릭 한 번으로 원하는 유니티 프로젝트에 임포트**해 주는 도구입니다.
BOOTH 라이브러리 페이지에서 `프로젝트 → 태그 → ▶ Unity로` 순서로 고르면 다운로드, 압축 해제, 임포트, 폴더 정리까지 자동으로 진행됩니다.

> **v0.3은 v0.2와 사실상 다른 프로그램입니다.**
> 이름과 저장소만 이어받았고 구조 대부분을 새로 만들었습니다. 여러 유니티 프로젝트 지원, 크롬 사이드패널/관리 페이지, 찜목록 정리가 새로 들어갔고, 크롬 확장·로컬 앱·유니티 패키지 모두 새 버전끼리만 맞물려 동작합니다.
> v0.2를 쓰던 분은 아래 [v0.2에서 옮겨오기](#v02에서-옮겨오기)를 먼저 읽어 주세요.

## 무엇을 해주나요

- **원클릭 임포트**: BOOTH 라이브러리의 파일마다 `[프로젝트▾][태그▾][▶ Unity로]` 버튼이 생깁니다.
- **여러 유니티 프로젝트**: ALCOM / VCC 프로젝트 폴더를 등록하면 그 안의 프로젝트를 자동으로 찾아 목록에 보여줍니다.
- **꺼져 있어도 예약**: 유니티가 꺼져 있는 프로젝트로 보내면 대기열에 넣어두고, 그 프로젝트를 켜는 순간 자동으로 임포트합니다.
- **태그 = 폴더**: 태그 이름대로 `Assets/<임포트 위치>/<태그>/` 아래에 정리됩니다. 프로젝트마다 쓸 태그를 따로 고를 수 있습니다.
- **어디에 넣었는지 기억**: 라이브러리에 `슈슈 · 임포트됨`, `홈월드 · 대기` 같은 배지가 붙습니다.
- **찜목록 정리**: 이미 산 상품을 **풀팩 구매 / 일부 구매 / 구매**로 구분해서 찜 리스트로 분류하거나 찜에서 지웁니다.

## 구성

세 가지가 함께 동작합니다.

| 구성 | 하는 일 |
| --- | --- |
| **크롬 확장** | BOOTH 페이지에 버튼을 붙이고, 다운로드를 시작하고, 사이드패널·관리 페이지를 보여줍니다. |
| **로컬 앱** (`BoothImportManager.exe`) | 받은 파일을 보관 폴더로 옮기고, zip을 풀고, 프로젝트별 대기열에 넣습니다. 백그라운드에서 조용히 돌아갑니다. |
| **유니티 패키지** | 각 유니티 프로젝트 안에서 자기 대기열을 지켜보다가 패키지를 임포트하고 태그 폴더로 정리합니다. |

```text
BOOTH 라이브러리  ──[▶ Unity로]──▶  크롬 확장 (다운로드)
                                       │
                                       ▼
                         로컬 앱: 보관 폴더로 이동 → zip 해제 → 프로젝트 대기열
                                       │   보관폴더\_projects\<프로젝트>\<태그>\*.unitypackage
                                       ▼
                         유니티 패키지: 임포트 → Assets\<임포트 위치>\<태그>\ 로 정리
```

## 설치

[Releases](../../releases) 에서 최신 버전의 파일 세 개를 받습니다.

| 파일 | 용도 |
| --- | --- |
| `BoothImportManager-v0.3.x.exe` | 로컬 앱 |
| `BoothImportManager-ChromeExtension-v0.3.x.zip` | 크롬 확장 |
| `BoothImportManager-Unity-v0.3.x.unitypackage` | 유니티 패키지 (선택 — 관리 페이지에서 원클릭 설치 가능) |

### 1. 로컬 앱

1. exe를 원하는 폴더에 두고 실행합니다. (예: `D:\Tools\BoothImportManager\`)
   - 설정 파일(`config.json`)과 기록 파일이 exe 옆에 만들어지므로, 바탕화면이나 다운로드 폴더보다는 전용 폴더를 추천합니다.
2. 처음 실행하면 브라우저에 예전 방식의 웹 화면(`http://127.0.0.1:7831`)이 열립니다. 닫아도 앱은 계속 돌아갑니다.
3. **윈도우 시작 시 자동 실행**: exe 바로가기를 만들고 `대상` 끝에 ` --background`를 붙인 다음, `Win + R` → `shell:startup` 폴더에 넣습니다. (`--background`는 브라우저를 열지 않고 조용히 시작합니다.)
4. 앱을 끄고 싶을 때는 관리 페이지 → **설정** → **로컬 앱 종료**를 누릅니다.

> 윈도우 SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있습니다. 서명하지 않은 개인 제작 프로그램이라 그렇습니다. `추가 정보 → 실행`으로 열 수 있습니다.

### 2. 크롬 확장

1. zip을 풀어서 **지우지 않을 폴더**에 둡니다. (크롬은 이 폴더를 계속 읽습니다.)
2. 크롬 주소창에 `chrome://extensions` 입력
3. 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** → 1번 폴더 선택
5. 툴바의 퍼즐 아이콘에서 **Booth Import Manager**를 고정(📌)해 두면 편합니다.

### 3. 유니티 패키지

관리 페이지에서 프로젝트마다 **설치** 버튼을 누르는 방법이 가장 쉽습니다. ([처음 설정](#처음-설정) 3번)
직접 넣고 싶다면 `.unitypackage`를 유니티로 임포트해도 됩니다. (`Assets/BoothImportManager/`에 들어갑니다)

## 처음 설정

크롬 툴바의 확장 아이콘을 누르면 오른쪽에 **사이드패널**이 열립니다. 위쪽 **관리** 버튼을 눌러 관리 페이지를 엽니다.

1. **설정 탭 → 폴더**
   - **Chrome 다운로드 폴더**: 크롬 설정의 다운로드 위치와 같게 맞춥니다. (보통 `C:\Users\<이름>\Downloads`)
   - **보관 폴더**: 받은 파일을 모아둘 곳입니다. 용량이 넉넉한 드라이브를 추천합니다. (예: `D:\BoothAssets`)
   - `선택…` 버튼을 누르면 PC에 폴더 선택 창이 뜹니다.
   - **설정 저장**
2. **프로젝트 탭 → 프로젝트 폴더**
   - ALCOM / VCC 프로젝트가 모여 있는 폴더를 추가합니다. (예: `C:\Users\<이름>\ALCOM\Projects`)
   - 자주 쓰는 위치는 **찾은 위치** 버튼으로 바로 추가할 수 있습니다.
   - 다른 곳에 따로 있는 프로젝트는 **폴더 밖에 있는 프로젝트 하나만 추가**로 넣습니다.
3. **프로젝트 탭 → 인식된 프로젝트**
   - 쓸 프로젝트마다 **유니티 패키지 → 설치**를 누릅니다. 유니티가 켜져 있으면 바로 컴파일됩니다.
   - **임포트 위치**: 에셋이 들어갈 폴더입니다. (예: `Assets/BoothAssets`) 비워두면 `Assets` 바로 아래에 태그 폴더가 생깁니다.
   - 안 쓰는 프로젝트는 **숨기기**로 목록에서 뺄 수 있습니다.
   - 표시 이름 칸에 별명을 넣을 수 있습니다. (예: `New Project` → `테스트용`)
4. **태그 탭**에서 태그를 정리합니다. 태그 이름이 유니티 안의 폴더 이름이 됩니다. (`01.헤어`, `02.옷`처럼 숫자를 붙이면 순서대로 정렬돼서 보기 좋습니다)
5. **프로젝트별 태그 탭**에서 프로젝트마다 쓸 태그를 체크합니다. (아래 [관리 페이지](#관리-페이지) 참고)

## 사용법

### BOOTH 라이브러리에서 바로 임포트

[BOOTH 라이브러리](https://accounts.booth.pm/library)를 열면 파일마다 버튼 줄이 붙어 있습니다.

1. **프로젝트** 선택 — `● 실행 중` / `○ 꺼짐`, 대기 중인 개수가 같이 보입니다.
2. **태그** 선택 — 그 프로젝트에 할당한 태그만 보입니다. (프로젝트를 먼저 골라야 활성화됩니다)
3. **▶ Unity로** 클릭

그다음은 자동입니다: 다운로드 → 보관 폴더로 이동 → zip 해제 → 대기열 → 유니티 임포트 → 태그 폴더로 정리.

편의 기능:

- **전부 Unity로**: 상품 카드 위쪽 버튼으로 그 상품의 파일을 한 번에 보냅니다. (풀세트처럼 파일이 여러 개일 때)
- **선택 따라가기**: 한 줄에서 프로젝트/태그를 고르면 같은 페이지의 다른 줄도 같은 값으로 맞춰집니다.
- **기억**: 마지막에 고른 프로젝트와, 프로젝트마다 마지막에 쓴 태그를 기억합니다.
- **재다운로드 없음**: 이미 받아둔 파일을 다른 프로젝트로 보내면 다시 받지 않고 보관 폴더의 파일을 씁니다.
- **상태 배지**: `슈슈 · 대기`, `슈슈 · 임포트됨`, `실패`처럼 프로젝트별 상태가 보입니다. 유니티가 임포트를 끝내면 몇 초 안에 바뀝니다.
- BOOTH 원래의 **Download** 버튼으로 받아도 상품 정보는 기록됩니다. 이렇게 받은 파일은 사이드패널의 **받은 파일**에서 나중에 보낼 수 있습니다.

### 사이드패널

확장 아이콘을 누르면 열립니다.

- **위쪽 ① 프로젝트 ② 태그**: 받은 파일을 보낼 대상입니다. 프로젝트 상태(실행 중/꺼짐, 패키지 설치 여부)도 여기 표시됩니다.
- **받은 파일 탭**
  - 필터: 미처리 / 전체 / 대기 중 / 임포트됨
  - 파일을 눌러 선택한 뒤 **③ ▶ Unity로**
  - **숨김**: 목록에서만 숨깁니다. 파일은 남아 있습니다.
  - **삭제**: 보관 폴더에서 실제로 지웁니다. 두 번 눌러야 지워집니다.
- **대기열 탭**: 프로젝트별로 아직 임포트되지 않은 파일과 실패한 파일을 보여줍니다. **취소**, **재시도**가 가능합니다.
- **찜 정리 탭**: 아래 [찜목록 정리](#찜목록-정리) 참고

### 상품 페이지 패널

BOOTH 상품 페이지 오른쪽 아래에 작은 패널이 뜹니다. (산 적 없고 무료 파일도 없는 상품에서는 뜨지 않습니다)

- 구매 형태: **풀팩 구매 / 일부 구매 / 구매함**, 일부 구매면 산 옵션 이름
- 이 상품을 어느 프로젝트에 임포트했는지
- 무료 배포 파일이 있으면 바로 **▶ Unity로**
- `–` 버튼으로 접어둘 수 있고, 접은 상태가 기억됩니다.

### 찜목록 정리

이미 산 상품이 찜목록에 남아 있으면 구매 형태별로 정리합니다.

1. 사이드패널 → **찜 정리**
2. 구매 형태마다 할 일을 고릅니다.

   | 구매 형태 | 뜻 | 기본값 |
   | --- | --- | --- |
   | **풀팩 구매** | 풀세트/전체 옵션을 샀음 | `풀팩 구매` 리스트로 분류 |
   | **일부 구매** | 여러 옵션 중 일부만 샀음 (예: 내 아바타 대응판만) | `일부 구매` 리스트로 분류 |
   | **구매 (옵션 1개)** | 옵션이 하나뿐인 상품을 샀음 | `구매` 리스트로 분류 |

   할 일: **리스트로 분류**(리스트 이름은 바꿀 수 있음) / **찜 삭제** / **그대로**
3. **미리보기** — 라이브러리와 상품 정보를 읽어서 무엇이 바뀔지 보여줍니다. (상품 수에 따라 시간이 조금 걸립니다)
4. **실행** — 한 번 더 눌러야 확정됩니다.

리스트가 없으면 자동으로 만들어집니다. 상품이 원래 들어 있던 다른 찜 리스트는 그대로 둡니다.

**풀팩/일부 판별 기준** — BOOTH 상품 정보의 옵션별 구매 기록을 봅니다.

- 유료 옵션이 1개뿐 → **구매**
- 유료 옵션을 전부 샀음 → **풀팩 구매**
- 가장 비싼 '풀세트류' 옵션을 샀음 (이름에 Full / フル / セット / Set / Pack / 全部 / 풀 등) → **풀팩 구매**
- 옵션이 3개 이상이고, 혼자 제일 비싼 옵션을 샀음 → **풀팩 구매**
- 그 외 → **일부 구매**

### 관리 페이지

사이드패널의 **관리** 버튼, 또는 라이브러리 안내 배너에서 엽니다.

- **프로젝트**: 프로젝트 폴더 등록, 인식된 프로젝트 목록(실행 상태, 대기/실패 개수, 유니티 버전), 유니티 패키지 설치/업데이트, 임포트 위치, 숨기기, 별명
- **태그**
  - 추가 (`모든 프로젝트에 추가` 체크 시 직접 선택 중인 프로젝트에도 바로 들어감)
  - 이름/색 바꾸기, `↑` `↓` 순서 바꾸기
  - **복제**: 같은 프로젝트 할당까지 그대로 복사 (비슷한 태그를 하나 더 만들 때)
  - **삭제**: 두 번 눌러야 지워짐. 프로젝트 할당에서도 같이 빠집니다.
  - **태그 세트 복사/붙여넣기**: 현재 태그 구성을 텍스트로 복사해서 다른 PC나 친구에게 줄 수 있습니다. 붙여넣으면 이름이 같은 태그는 건너뛰고 새 것만 추가합니다. 한 줄에 태그 이름 하나씩 적어서 붙여넣어도 됩니다.
- **프로젝트별 태그**: 가로가 프로젝트, 세로가 태그인 표입니다.
  - **제한 없음**: 모든 태그를 씀 / **직접 선택**: 체크한 태그만 씀
  - **전체 / 해제**: 그 프로젝트의 태그를 한 번에 켜고 끔
  - **복사해오기…**: 다른 프로젝트의 태그 구성을 그대로 복사
  - 줄 끝의 **모두 켜기 / 모두 끄기**: 그 태그를 모든 프로젝트에서 켜고 끔
  - `태그 없음`은 항상 사용합니다. (임포트 위치 바로 아래에 넣고 싶을 때)
- **설정**: 폴더, 동작 옵션, 로컬 앱 포트, 로컬 앱 종료

## 유니티가 꺼져 있을 때

- 꺼져 있는 프로젝트로 보내면 대기열(`보관폴더\_projects\<프로젝트>\`)에 넣어둡니다. 배지는 `대기`로 보입니다.
- 그 프로젝트를 켜면 유니티 패키지가 대기열을 확인하고 **오래된 것부터 차례로** 임포트합니다.
- 플레이 모드 중이거나 컴파일 중이면 끝날 때까지 기다렸다가 임포트합니다.
- 임포트가 실패한 패키지는 `.failed`로 이름이 바뀌어 무한 반복하지 않고, 사이드패널 **대기열**에서 재시도할 수 있습니다.
- 실행 중인지는 유니티가 10초마다 남기는 신호로 판단합니다. 그래서 유니티 패키지를 설치한 뒤 한 번 열어야 `● 실행 중`이 정확하게 나옵니다.

## 폴더 구조

```text
보관 폴더 (예: D:\BoothAssets)
├─ 받은 파일들.zip / .unitypackage
├─ 받은 파일 이름\            ← zip을 푼 폴더 (다른 프로젝트로 보낼 때 재사용)
├─ _projects\
│  └─ <프로젝트키>\           ← 프로젝트마다 하나
│     ├─ 02.옷\상품.unitypackage   ← 대기 중
│     ├─ project.json         ← 임포트 위치 등 (관리 페이지에서 저장)
│     └─ .heartbeat.json      ← 유니티 실행 신호
└─ _queue\                    ← v0.2 방식 공용 대기열 (예전 웹 화면에서 보낼 때)

유니티 프로젝트
└─ Assets\<임포트 위치>\<태그>\<상품 폴더>\...
```

`프로젝트키`는 프로젝트 경로로 만든 짧은 해시 + 폴더 이름입니다. (예: `303c755a_슈슈`)

## v0.2에서 옮겨오기

1. **예전 크롬 확장 "Booth Import Manager Bridge"를 삭제**합니다. 둘 다 켜져 있으면 같은 다운로드를 두 번 처리합니다.
2. 예전 exe를 끄고 새 exe로 바꿉니다. 예전 `config.json`을 새 exe 옆에 두면 폴더와 태그 설정을 그대로 씁니다.
3. 관리 페이지 → 프로젝트 탭에서 각 프로젝트의 유니티 패키지 칸을 봅니다.
   - `Assets 안 (이전 방식)` 으로 보이면 **v0.3로 업데이트**를 누릅니다. 기존 위치(`Assets/BoothImportManager/Editor`)의 파일을 그 자리에서 바꿔서, 두 벌이 되어 컴파일 에러가 나는 일을 막습니다.
   - `.unitypackage`로 직접 업데이트하려면 **기존 `Assets/BoothImportManager` 폴더를 먼저 지우고** 임포트하세요. 그대로 덮으면 스크립트가 두 벌이 될 수 있습니다.
4. 예전 웹 화면(`http://127.0.0.1:7831`)도 계속 쓸 수 있습니다. 거기서 보낸 파일은 공용 대기열(`_queue`)로 가고, 유니티 패키지 설정의 `v0.2 공용 큐도 감시`가 켜진 프로젝트가 가져갑니다.
5. 달라진 점
   - 웹 화면 탭을 닫아도 앱이 꺼지지 않습니다. (설정에서 바꿀 수 있음)
   - 로컬 앱이 크롬 확장과 자기 화면에서 온 요청만 받습니다. (v0.2는 아무 웹사이트에서나 로컬 앱의 삭제 기능을 호출할 수 있었습니다)

## 자주 묻는 질문 / 문제 해결

**사이드패널에 "로컬 앱이 꺼져 있어요"라고 나와요**
exe가 실행 중인지 확인하세요. 작업 관리자에서 `BoothImportManager.exe`를 찾을 수 있습니다. 포트를 바꿨다면 관리 페이지 설정의 포트도 같아야 합니다.

**▶ Unity로를 눌렀는데 "Supported downloaded file not found"가 떠요**
크롬 다운로드 위치와 관리 페이지의 **Chrome 다운로드 폴더**가 다른 경우입니다. 두 곳을 같게 맞춰 주세요. 크롬 설정에서 **다운로드 전에 각 파일의 저장 위치 확인**이 켜져 있으면 매번 저장 창이 뜨니 꺼 두는 것을 추천합니다.

**프로젝트 목록이 비어 있어요**
관리 페이지 → 프로젝트 폴더에 프로젝트들이 들어 있는 **상위 폴더**를 넣었는지 확인하세요. 유니티 프로젝트는 `Assets`와 `ProjectSettings` 폴더가 둘 다 있어야 인식됩니다. (두 단계 아래까지 찾습니다)

**계속 `○ 꺼짐`으로 나와요**
그 프로젝트에 유니티 패키지를 설치했는지 확인하고, 유니티를 한 번 열어 주세요. 유니티 메뉴 `Tools > Booth Import Manager > Settings`에서 Project key와 Intake folder가 보이면 정상입니다. Intake folder가 비어 있으면 로컬 앱을 한 번 실행한 뒤 유니티를 다시 여세요.

**대기에서 넘어가지 않아요**
- 유니티 창을 한 번 클릭해 보세요. 유니티는 창이 뒤에 있을 때 일부 처리를 미룹니다.
- 플레이 모드를 끝내면 임포트가 시작됩니다.
- 콘솔에 `[BoothImportManager]` 로그가 있는지 확인하세요.

**압축 파일 안에 unitypackage가 없어요 (`패키지 없음`)**
텍스처나 PSD만 들어 있는 상품입니다. 보관 폴더에 풀어둔 폴더를 직접 쓰면 됩니다.

**찜 정리 미리보기가 안 돼요**
BOOTH에 로그인되어 있어야 합니다. 정리 중에는 BOOTH 탭이 잠깐 열렸다 닫힐 수 있습니다.

**유니티에 컴파일 에러가 나요 (같은 클래스가 두 번 정의됨)**
`Assets/BoothImportManager`와 `Packages/local.booth-import-manager` 두 곳에 다 들어간 경우입니다. 하나를 지워 주세요. (관리 페이지의 설치/업데이트 버튼을 쓰면 이런 일이 생기지 않습니다)

## 알아둘 점

- BOOTH(pixiv)의 공식 도구가 아닙니다. BOOTH 화면 구조가 바뀌면 버튼이 안 붙거나 찜 정리가 실패할 수 있습니다.
- 찜 정리는 BOOTH 웹사이트가 쓰는 기능을 내 로그인 상태로 그대로 호출합니다. 처음에는 몇 개만 정리해 보고 결과를 확인하는 것을 추천합니다.
- 받은 에셋의 이용 약관은 각 상품의 약관을 따릅니다. 이 도구는 파일을 옮기고 임포트만 합니다.
- 이미 유니티 프로젝트에 들어 있는 에셋 폴더를 다시 분류할 때는 [Unity Asset Classifier](https://github.com/Luin48/Unity-Asset-Classifier)를 추천합니다.

직접 빌드하는 방법은 [docs/build.md](docs/build.md)에 있습니다.
